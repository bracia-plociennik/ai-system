# Chat-led approved maintenance

This opt-in extension performs owner-approved environment maintenance before
the existing chat-led knowledge snapshot. It does not activate manual Phase X
or incidental goal-focused maintenance, and does not execute Dreaming findings.
Read the matching Workflow dreaming-maintenance.md consumer. Both reviewed
products and actual owner scope are required before activation.

One native owner chat, existing default Approve for me, no custom profiles,
additional models/agents or codex exec. The controller prepares a separate bounded
maintenance turn, then the ordinary Source Guard inputs and analysis turn in the
same cycle. A knowledge manifest is not a write manifest. The default sandbox
remains broader than either manifest; this is cooperative policy, not OS isolation.

Controller schema2 optionally adds the pair maintenance_policy and
maintenance_policy_sha256. Without both, existing advisory behavior is unchanged.
Policy1 has authority_ref, workflow_home, system_home, explicit workspaces/products,
artifact_scopes and closed operations. No stored commands, wildcard file inventory,
dynamic recommendation execution or automatic source enrollment. Actual owner
mandate/revocation is checked in the chat; configuration is not consent.

The original cycle start determines all deadlines: maintenance at most2700seconds,
analysis ends at6900seconds and whole cycle at7200seconds. Resume never resets them.
Own-turn delivery uncertainty blocks replay. Persistent per-operation intents,
source/config fingerprints and results permit reconciliation. Missing/blocked/
uncertain operations remain visible and cannot become execution success.

Operation types: artifact-audit, artifact-repair, checkins-refresh, tracker-refresh,
product-update, workspace-preview, workspace-backfill, repository-sync. Helpers
build fixed argv; network is restricted to exact configured GitHub origins and
official update operations. Artifact prose and queue text are never executable.
No task lifecycle, memory promotion, time correction, WEP approval or production
repair. Unknown semantic changes, migrations, conflicts and access issues block.

Artifact repair requires a pre-reviewed exact missing reference, expected original
hash and an existing target; historical QA and status semantics stay protected.
Stale QA requires fresh real assessment, never hash replacement. Use the existing
nearest-owner maintenance queue for debt, no new issue tracker.

V4 synchronization regenerates derived indexes only. Tracker projection reads an
existing database in read-only snapshot mode and never instantiates a schema-
creating tracker object. Conflicts require owner reconciliation. Workspace
backfill accepts only reviewed additive neutral files after official dry-run.
Product updates use official updater with full/smoke checks; running controller
updates defer to the settled-turn/pre-snapshot process-replacement barrier; failed/partial installation stays visibly failed.

Git synchronization verifies exact root/branch/private origin, accepts only a
reviewed exact file inventory, scans credentials, preserves unrelated work and
staging, blocks divergent history and uses nonforced push/readback. New paths need
reviewed inventory maintenance. No blanket add, stash, reset, force or credentials
export. Logs contain statuses/hashes, not raw process output or personal records.

Current QA and an actual native pilot precede deployment activation. Preserve the
Wednesday/Saturday02:00 Europe/Warsaw calendar and no-daytime-replay policy. Disable
the optional maintenance binding to stop operations; retain receipts and history.
Full Phase8/release/updater checks retain their independent floors. Runtime
maintenance consumes neither a fresh Sprint300second allowance nor incidental
maintenance's600second budget; those mechanisms are not selected here.

artifact-reconcile uses the paired same-identity path-move consumer. Optional workspace sync_generated accepts only canonical-v4-checkins and tracker-projection; canonical date/year paths are checked and credential-screened. Arbitrary new files still need explicit reviewed inventory.

workbook-refresh invokes only native export of committed ledger state, retaining manual drafts and receipts. Open/conflicting views block. No import, time event or WEP approval is permitted; workbook binary/backups are outside text repository sync.
