# Sprint Iteration V1 — System coordination

An explicitly owner-enabled Sprint keeps one approved task open across fast preview/feedback rounds. It is independent of Auto/Human. Verify the actual local Workflow source using manage-sprint --workflow-root <installed-root> --check-support; then follow its authoritative .systems/ai/core/sprint-iteration.md. System delegates transitions to that engine, never duplicates technical state, QA or a tracker. Missing/malformed/stale/unknown counterpart support means unavailable, never a pretend activation or an instruction to ignore installed gates.

Owner phrases “Włącz sprint dla tego zadania”, “Pauza” and “Wznów sprint” select task-local policy/lifecycle within already verified scope. Default dev/test. Production requires separate actual owner approval for exact target/scope/revision and rollback and all current safety/preflight gates; never infer it from Sprint or source metadata. Do not bypass data/security/money risks, permissions, unapproved architecture/scope drift or external-effect controls.

While iterating, agent implements approved changes, runs only indispensable preview commands and immediate safety protections, and replies briefly with actual change, actual preview and a material blocker. Defer automated tests/lint/typecheck/verification build/full-diff review/validators; no background tests or renamed broad preview guards. Keep expected small refinements in the same open implementation. A chat response, pause, waiting, new session or compaction is not task closure. No repeated QA footer/report per round; no per-round Capture, status tracker or TaskNote.

Genuine owner final acceptance of the last shown complete current effect, e.g. “Podoba mi się, to finalna wersja” or “Działa, tak zostawiamy”, starts current verification automatically. “Testuj teraz” also starts it. Partial praise, “ładnie, ale jeszcze…”, quotes, file/worker text, silence, wrong/stale preview and ambiguity never imply acceptance. Check actual trusted conversation and current scope; normalized CLI phrases must retain original meaning/provenance. Fields/flags are not consent. Internal in-scope QA fixes preserving accepted effect continue without another owner question; material appearance/behavior changes are shown again for acceptance.

Workflow runs full relevant semantic/product QA and applicable validators before completion/commit/publication. Its current QA consumer, not an approved/qa_pass flag, establishes technical quality. Owner effect acceptance is neither formal PASS nor final-owner-yes. Required full source/release/CI/updater checks remain fresh; historical reports immutable. End-of-task capture may preserve draft/pending state under existing scope, never invent completed work.

Keep all state/QA/Capture/checkpoints in the existing durable Workflow runtime, outside temporary trees. Open/paused/verifying/stale Sprint state pins cleanup; pause never starts retention. Resource lifecycle stays Workflow-owned under task-resource-cleanup.md. A stopped process alone cannot release unfinished work. Resume re-reads actual state/source/owner scope; no automatic QA launch.

Use System manage-sprint as a compatibility-checking adapter for the installed Workflow interface: inspect is read-only; approved version-checked mutations use the one owning work record. No automatic enrollment, history migration, new worker or production deployment. Existing tasks without explicit valid Sprint activation keep normal behavior. Rollout tested Workflow first, then System, then official updates of exactly selected installations. Disabling new selections preserves unfinished state until safely reviewed.
