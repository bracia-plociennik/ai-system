# Default Sprint V2

## Applicability and authority
New approved implementation tasks use Sprint V2 by default when the installed consumer/producer supports this exact source-verified capability. This is task policy selection, not permission, project enrollment or native execution proof. Read-only, questions, planning, and explicit non-Sprint owner instructions keep their appropriate routes. Verify scope, DoD, preview, ownership, accepted planning and risk first. Explicit owner decisions win; unsupported installations retain installed gates. Do not activate this capability to validate its own implementation.
Existing schema1 records retain sprint-iteration.md V1 semantics; no conversion, backfill, historical report rewrite or reopening. New CLI start defaults to --schema 2; --schema 1 is explicit compatibility. The owning Workflow record is the only technical state; System delegates, never copies it.

## Make it work
Run only indispensable dev/test preview commands and immediate protections. Defer tests, lint, separate typecheck, verification builds, broad diff review and framework validators; no background or renamed preview checks. Show the actual effect (UI preview or backend demonstration), retain scope and next action in existing work evidence. No new phase or QA/Capture per round. Pause, resume, chat end, praise of part of the effect and Auto do not start checks or close work. Source fingerprints, shown preview, actual owner provenance and scope remain mandatory.
Never postpone safeguards needed before real data, money, secrets, security/permission boundaries, production or external effects. Material unapproved goal/architecture drift is immediate. Publication, production, CI and official updater gates stay independently mandatory; Sprint never authorizes deployment of an unchecked MVP.

## Acceptance and bounded targeted QA
Acceptance of the complete current effect or an explicit targeted verification request begins a cycle for that accepted source. Acceptance is not final-owner-yes. Whole-project inspection requests are explicit full-verification scope, not inferred from praise. Partial/stale/quoted/worker requests remain inadmissible.
The TOTAL allowance is 300 seconds including selection, semantic review, checks, in-scope corrective work and recording. The engine starts a persisted wall-clock budget at acceptance, conservatively including gaps; pause/resume, new process, retries and corrections never reset it. A backwards/unknown clock blocks further checks. Only a genuinely changed and re-shown/reaccepted effect can start another cycle; identical fingerprints cannot renew allowance.
Use manage-sprint qa-run with a directly supplied reviewed argv after -- for automated checks: no commands stored in data are executed. Its timeout is the remaining allowance, process-group termination preserves available logs, failures remain failures. The wrapper is not an OS sandbox or authority for the command. No nested shell/background checks or detached children to escape the allowance. A hard kill of the parent conservatively consumes the still-running budget; inspect existing processes before resuming, never launch a duplicate.
complete-targeted --result passed|failed|incomplete --report <owning reviews evidence> records actual scope, findings, executed/skipped checks and residual risk. Exhausted, timed-out or failed checks cannot become passed. A manual-only review may be sufficient only with a stated scope-specific basis. A passed targeted result is not formal implementation-quality PASS. Modified reports/source invalidate current confidence. Preserve negative evidence; no automatic retry budget. Budget overrun necessary to safely stop a process is reported honestly.

## Incremental phases5–7
For schema2 only, bounded targeted QA is the incremental phase5 route. Phase6 records compact findings/knowledge disposition and remaining full checks, without invented complete distillation. Phase7 reviews goal, scope, dependency changes and safety using current targeted evidence; it does not trigger full source/framework validation solely from checkpoint cadence. Three-task and final checkpoints remain coordination stops, not automatic hardening work.
A successful targeted result may support an independently safe next implementation task. Incomplete evidence supports only demonstrably independent work whose required behavior does not depend on it; failed relevant behavior blocks dependent tasks. Existing formal QA consumers do not accept targeted evidence as implementation-quality. Coordinator sprint_progress describes continuation separately while verified_qa/gate remain truthful. No completed-project/PASS, final closure, production readiness or resource release follows. This specific V2 routing supersedes ordinary full phase5/source-checkpoint requirements while implementation stays open; other work retains installed routing.

## Make it right: explicit full verification / Phase8
Only a real owner request covering the concrete project/scope starts request-full-verification; Auto, implementation-range, resume, accepted preview or an agent's readiness recommendation never starts Phase8. V2 full requests use --origin owner --message 'Uruchom Phase 8' (or another documented exact full request) and original --owner-reference. This selection never supplies final-owner-yes.
Full verification reviews the complete accepted project/dependency scope, regressions, negative paths, security, applicable validators, deferred work and required phase6/7 artifacts. Run outstanding full-required source checks with smoke, preserve their real result and review failures. Unrelated historical maintenance belongs in Phase X; do not label a scoped check a successful exhaustive full audit. Direct missing dependencies still block the project.
complete still consumes current full implementation-quality through the established QA verifier. Targeted reports cannot satisfy it. Full technical QA and actual final-owner-yes are independently required for Phase8 closure. An actual trusted owner instruction may explicitly authorize conditional closure of the exact reviewed scope after required QA succeeds; it is recorded as owner authorization, never an inferred PASS. Material scope changes need their actual decisions.

## Persistence, compatibility and release
States iterating/paused/targeted/targeted-checked/targeted-incomplete/targeted-failed remain pending full quality. verifying requires an explicit full_request; verified additionally requires established current QA. Existing source identity, complete preview scopes, CAS/common-Git lock, report integrity and task-resource cleanup guards remain. Pending resources stay pinned; retain durable evidence outside .tmp/.worktrees.
refresh-verification requires a current semantic correction review for effect-preserving in-scope fixes; it never renews targeted time. Changed accepted appearance/behavior needs a new shown effect. No timer, scheduler or background worker is installed.
Consumer first, producer second, selected official updates last. Keep dev, source-only main publication and immutable old QA. CI, release and updater validation stay fresh and are not bound to the targeted allowance. Disable new V2 selection to roll back default behavior; preserve existing pending states. Full checks for this feature use the preexisting installed rules, not this feature's deferrals.
