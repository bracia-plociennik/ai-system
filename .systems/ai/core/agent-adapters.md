# Agent Adapters

## Codex v1

`manage-agent-adapter inspect` is read-only and the default. `plan --system-home <absolute-management-root> --owner-workspace-id <id> --owner-asset-id <id>` prints an inert, source-bound plan. Save it privately and review its exact targets. `apply --plan <path> --approved` requires actual scoped owner approval: the flag and plan hash cannot authenticate consent. This installs only the managed fragment in the selected user's Codex AGENTS.md and a user registration; it does not edit provider credentials, sandbox settings, Git roots or project files.

The installer requires an explicit management role, an existing registered workspace and owned asset. It refuses global override shadowing, oversized guidance, unsafe links and unknown/rebound installations. Receipt storage is the selected asset's assets/agent-adapters/receipts/codex/<transaction>/transaction.json, with hashes and the old owned fragment only. Existing unrelated instructions are never backed up to the receipt. No secrets or complete home are copied. Private files use restricted modes. A nonblocking per-user writer lock prevents simultaneous transactions.

Each apply compares its reviewed base immediately before writing. It records pending state, disables registration, replaces only its owned fragment, enables registration and writes the applied receipt last. Both enabled registration and applied receipt are required for activation. An interrupted apply can resume using the same plan; changed inputs stop it. Reapplying an intact applied plan is a no-op. Disabling withdraws registration. `restore --receipt <path> --approved` withdraws the managed fragment and restores only its known registration/fragment predecessor, preserving unrelated user edits. Changed owned fragments or registration require review. Restore is resumable and remains available when source versions change; receipts and history remain preserved. No automatic rollback, retry or installation during an updater.

The resolver observes Codex's selected global and repo-to-CWD AGENTS/AGENTS.override chain, flags overrides and a combined automatic instruction population above 16 KiB, and records file hashes. Custom provider filename configuration is outside v1 automatic support and requires deliberate verification. Project-local Workflow loads its detailed guidance on trigger. Native memory controls are explicitly unsupported by this adapter: it neither edits provider config nor claims native auto-memory is disabled. Actual CLI memory state must be observed separately; canonical memory writes always require their own real scope.

A source capability verifies declared relevant bytes, not unrelated HEAD changes, actor identity or native behavior. Every concrete installation needs observed native acceptance; files or green schema checks are insufficient. Model/native test limits belong to the stable owning task and survive resumes. Missing model/login/tool/permission is a truthful affected prerequisite, never permission to broaden access or switch model silently.

## Claude Code MVP design — inactive

Expose the same inspect/plan semantic interface with `--tool claude-code`: status design-only, activation_supported=false, native_verification=unverified. Apply, disable and restore are deliberately unavailable. No Claude installation, login, native invocation, CLAUDE.md edits, trust bypass or memory configuration occurs in v1. A future adapter must explicitly detect installed version, ancestor/project CLAUDE.md suppression of default AGENTS loading, existing imports, accepted external paths and native memory controls, then choose one owned load chain while preserving existing content. A refused import, old version or ambiguous chain blocks only affected activation. Test S20/S21 is deferred by the owner's current Codex-only amendment; it must not be labeled a native pass.

## Other tools and web chats

`--tool generic` exposes the same design-only status. A future adapter implements versioned inspect/plan/apply/disable/restore and the same scope, receipt, interruption and shadow semantics using its native instruction mechanism. A non-local chat can receive a minimal privacy-reviewed exported context bundle describing source version, task scope and unavailable capabilities. That bundle is advisory data, grants no filesystem/tool/owner authority and cannot impersonate live installed state. Do not export private memories or secrets by default.
