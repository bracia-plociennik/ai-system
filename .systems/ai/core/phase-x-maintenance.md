# Phase X — Maintenance

Phase X is an independent manually requested maintenance session, not a required step after Phase8. No automatic trigger from Auto/autopilot, idle time, task completion, thresholds or Dreaming. Future Dreaming execution requires separately approved design and activation. Existing Dreaming remains advisory.

## Routing and ownership
Use `Phase X --workspace <absolute-path>` or `Phase X -all`. Without a selector use only an unambiguously resolved current owning workspace; ambiguity stops affected work. The read-only manage-maintenance helper prints selected targets and execution_authorized=false; it does not grant consent or execute repairs. For System -all use the verified installation home registry, including available active/paused/archived entries; planned/unavailable entries are pending and must be reported, never auto-created. No directory crawling or automatic enrollment. Workspace names/queue text never grant authority. Native AI agents perform covered actions after actual ownership, risk and tool checks.
Standalone Workflow defaults to its resolved owning runtime; -all needs verified System registry access and actual cross-workspace mandate. Relative paths are resolved from the verified installation, HOME expressions use the local environment, no fixed home prefix. Keep owners isolated; preserve raw private data in its owning workspace.

## Manual execution procedure
1. Resolve selected owners and capture the actual owner request in existing work evidence. Inspect existing queues, status, current QA/Capture links, source/dependency bindings and environment; report real failures without restamping history.
2. Select applicable full validation per owning product/runtime, preserving scope and real outcomes. Missing sources/access remain pending. A failed owner does not stop independent selected owners.
3. Repair only understood local reversible maintenance within actual scope: current routers/pointers, factual current status and generated owner metadata with original evidence preserved. Semantic evidence reclassification needs explicit grounds and proper current evidence. Never invent original Spec, QA or completion.
4. Stop dependent repair for migrations, destructive changes, security/access/credentials, product behavior/architecture changes, production or external effects. Those need their actual separate approval/route. No push/publication from a maintenance command.
5. Recheck repaired scope; append factual results/dispositions to existing owner work evidence and queue. Preserve old QA bytes and queue history. Distinguish repaired, deferred, blocked and unverified. A summary for -all uses privacy-safe pointers, never copies private source between owners.

There is no new issue tracker, scheduler, command database or background executor. The 300-second Sprint QA allowance and incidental 600-second maintenance allowance are not budgets for explicitly requested Phase X itself. No unapproved time limit is invented. Phase X cannot retroactively close projects, waive current release checks, silently activate new installations or reset Sprint budgets.
